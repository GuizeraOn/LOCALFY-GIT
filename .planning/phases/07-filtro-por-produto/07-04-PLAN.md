  <action>
    Em `src/app/api/metrics/route.ts`:

    1. Ler o parâmetro: `const rawProductId = searchParams.get('productId');`
    2. Normalizar e validar logo após a checagem de `startDate`/`endDate`:
       - `const trimmed = (rawProductId ?? '').trim();`
       - `const productId = (trimmed === '' || trimmed === 'all') ? null : trimmed;`
       - Se `productId !== null` e NÃO casar com `/^[\w .:@|-]{1,120}$/` (allowlist: letras, dígitos, underscore, espaço, ponto, dois-pontos, arroba, pipe e hífen), devolver `NextResponse.json({ error: 'Invalid productId' }, { status: 400 })`. Nunca ecoar o valor recebido na mensagem de erro.
    3. Aplicar o filtro na consulta de vendas de forma encadeada, preservando os filtros de data:
       ```
       let salesQuery = supabaseServerClient
         .from('sales')
         .select('*, sale_utms(*)')
         .gte('created_at', `${startDate}T00:00:00.000Z`)
         .lte('created_at', `${endDate}T23:59:59.999Z`);
       if (productId !== null) { salesQuery = salesQuery.eq('product_id', productId); }
       const { data: sales, error: salesError } = await salesQuery;
       ```
       Não montar SQL por concatenação — `.eq()` do supabase-js é parametrizado.
    4. Não filtrar `ad_spend` nem `expenses` no SQL: esse recorte é responsabilidade de `calculateMetrics` (ele precisa dos gastos para descobrir quais campanhas venderam o produto).
    5. Passar o filtro adiante: `const metrics = calculateMetrics(sales || [], adSpends || [], expenses || [], { productId });`
    6. Manter `export const dynamic = 'force-dynamic'`, o try/catch, a validação `Missing startDate or endDate` e o corpo genérico de erro 500 já existentes.

| Rotas Next.js → Supabase (service role key) | Leitura privilegiada que ignora RLS |

| T-07-15 | Information Disclosure | mensagens de erro | mitigate | 400 devolve `Invalid productId` sem ecoar a entrada; 500 devolve `Internal server error` com o detalhe apenas em `console.error` |
| T-07-16 | Information Disclosure | `GET /api/products` | accept | A rota expõe nomes comerciais de produtos, mesmo nível de sensibilidade das métricas já expostas por `/api/metrics`; o app não possui autenticação de usuário nesta versão (limitação conhecida, herdada das Phases 1-6) |
